# 视觉证据纠偏与问题集验收设计

## 目的与边界

本阶段解决金融问答把不相关银行的视觉页排在前面、并据此拼凑答案的问题。保留当前活动的 920 份文档快照、文本/稀疏/结构化/视觉通道和现有 RRF；不重建知识库、不处理 3 份未转换 Office 文件、不调用付费模型或 Web 搜索。Web 搜索、持久任务和部署加固是后续独立阶段。

用户上传的 `test/merged.xlsx` 有 500 行问题，只有 `question_id`、`question` 两列，不能直接计算答案准确率。本阶段只做离线证据覆盖审计和少量人工可核对案例，不把模型自评当作正确答案。

## 已证实的故障

`FusionRetriever` 已用 `1/(60+rank)` 分别累加文本和图像名次，故障不是未使用 RRF，也不能从现有证据断言“图像原始分数压过文本”。`ChineseVisionRetriever.resolve_hits` 会把一页的多个切块连续展开到 top-k，使同一页占满图像候选。中文 CLIP 的视觉近似还可能把其他银行的页面排在正确实体之前。

第一道示例题询问“掌上银行”App 的基金服务和认购流程。当前 920 份快照的文本切块里，“掌上银行”仅在两段农业银行产品介绍中出现，未提供相应操作流程；“基金认购”命中的其他银行和通用培训材料也不构成该 App 的操作证据。正确的本地检索结果应承认证据不足，不能用别的银行流程补齐。

## 选择的方案

在视觉通道按唯一 `(document_version, page)` 排名：同一页最多贡献一个代表切块；代表切块优先选择与问题中显式实体/功能词重合的文本，缺少重合时使用确定性回退；无文本页保留 `page_image` 证据。跨页重复切块只保留最高排名的页。之后仍按现有 RRF 与文本融合，不加任意的大幅图像权重。

在进入生成之前，对问题中的显式银行或产品实体做保守的证据核对：例如“掌上银行”是 App 名，不推断成某家银行。候选片段不能凭其他银行的名称或泛泛“基金认购”充当 App 操作指南。如果支持具体操作的证据不足，返回明确的“库内证据不足”，保留已找到的来源和缺口说明；不臆造操作步骤。该门禁只针对可明确识别的实体和操作类问题，普通概念问题、跨银行比较问题和真正的纯图片证据不应被一概过滤。

## 数据流与接口

1. `ChineseVisionRetriever.search(query)` 把问题交给页命中解析；`resolve_hits` 接受可选问题文本，并返回至多 `top_k` 个不同页面的代表证据。既有调用 `resolve_hits(scores)` 保持兼容。
2. `FusionRetriever` 沿用 `text_rrf + image_rrf`，图像通道的页级去重发生在融合之前。来源 `document_version`、页码、`page_id`、图像哈希和可见性过滤保持不变。
3. Agent 已有 `_supports_named_app` 在评分前排除不包含“掌上银行＋基金”的证据，图流程在全无关时返回 `no_evidence`。本阶段保留并回归验证这一门禁，必要时只补充不足原因与测试；不重复造一套判定器。不能把空图像文本解释成已理解图片。
4. 验收脚本只读取 `test/merged.xlsx` 和活动快照，按工作表行号标识问题，保留重复题号/重复问题；输出 JSON/CSV 或 Markdown 统计，不修改原表。若运行在线模型，另设显式预算与调用上限，本阶段默认不调用。

## 错误处理与安全

索引缺页图、单页无切块、同一切块跨页、被权限过滤的页面，都不得导致重复证据或异常。问句没有可确定的实体时不做强制实体过滤；宁可报告“未验证”而不虚称已验证。已有活动快照和用户未提交改动不覆盖、不重置。只选择性提交可归属于本阶段的新文件；如改动叠在既有脏文件上，不把整份旧改动冒充本次提交。

## 验收标准

- 回归测试证明视觉 top-k 不再被同一页的多个切块占满；版本相同的跨页切块仍只出现一次，纯图片页仍可返回。
- RRF 分数由名次相加，图像原始相似度仍不覆盖文本相似度；来源、页码、可见性元数据不回退。
- “掌上银行＋基金认购流程”案例不引用别家银行的操作流程；库内无充分证据时明确拒绝编造。
- 500 行问题均能进入离线审计，重复行不丢失；报告区分“检索覆盖”与“答案准确率未评定”。
- 相关单元测试、现有视觉/检索回归测试通过；不调用付费 API，不切换或重建在线知识库。
