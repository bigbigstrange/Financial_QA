# Doubao 小样本全链路试跑设计

日期：2026-09-23。状态：已获用户确认。适用项目：`finance-qa-platform`。

## 目标与边界

用户希望用已授权的 Doubao-Seed-2.1-pro，在现有金融 RAG 项目中真实打通模型路由、证据评分、答案生成、双校验、图谱、视觉问答和前端事件展示，但不要求对 923 份业务文件进行付费全量处理。试跑必须保留现有 920 份文档的在线快照、混合检索和可追溯证据；不能把一次可用的演示说成全量覆盖或准确率达标。

2026-09-23 用户报告的 Pro 资源包剩余 2,499,950 tokens；每日 2,000,000 tokens 是采集上限，不与余额相加。设本项目本轮**目标消耗上限 1,500,000 tokens**，留约 1,000,000 tokens 余量。该本地上限不等于云厂商的计费封顶：其他应用并发用量、计量延迟或资源包抵扣规则变化仍可能产生账单。若控制台无法设置独立预算或禁用超额计费，任何付费批处理必须分批核对余额，不能承诺绝对零扣费。资源包自 2026-10-16 起陆续过期。

仅发送经检查的非敏感文档节选；不能把整份原始业务文件、密钥、个人信息或不明来源的内容上传以换取额度。密钥来自用户提供的本地文件，写入项目不入库的配置，不进入日志、测试快照或前端响应。

## 方案比较

1. **推荐：全量本地检索 + 有界付费小样本。** 复用已上线的文本、稀疏、结构化和视觉检索索引；只对精选六类问题和少量公开证据块开启模型推理、抽样图谱和视觉识别。覆盖技术链路，最符合现有余额。
2. 仅接入问答模型，不做图谱和图像：最快、最省额度，但达不到“所有方法都试通”。
3. 对全库做付费图谱和评测：旧估算约 6,570 万 tokens，远大于当前约 250 万 tokens，排除。

## 数据流和修改范围

沿用 `OpenAICompatibleTransport`，以最小改动给现有模型客户端增加 Ark 提供方配置和正确的 `ModelSnapshot` 归属，使用官方 Chat Completions 端点及 `doubao-seed-2-1-pro-260915`。不把 Ark 调用伪装成 DeepSeek。`FINANCE_DISABLE_PAID_API=1` 继续作为默认安全开关；仅在明确的试跑命令或人工启动的服务进程中开启，并保留一键关停能力。所有在线付费调用（路由、评分、重排、生成、两次校验和重试）必须写同一用量台账：调用节点、模型、输入/输出/总 tokens、耗时、结果和错误，不记录 prompt 正文或密钥。缺失 `usage`、模型不匹配、HTTP 402/429、预算预留不足时停止后续调用并显式报告，不降级成“验证通过”。

首个真实请求只做最小非敏感探针，先核对返回模型与 `usage`，再由用户控制台核对是否正确抵扣该 Pro 资源包。确认后按小批量问题放量；本地预算先预留单次最大输出和估算输入，调用结束再以实际 `usage` 结算。并发付费请求在试跑期限制为 1；无法证明跨进程共享预算的进程不得同时付费运行。已有 DeepSeek 相关配置和历史产物保留，配置切换不得重建或清空在线库。

在线问答仍走金融项目自己的多通道检索与证据契约，不接入用户明确拒绝的 `web_search`。路由和问题拆解保留“掌上银行”这一 App 限定；检索证据不支持具体银行或操作步骤时明确拒答或说明证据不足。生成后真正执行 groundedness 与答题相关性双校验，记录验证状态；失败的重试受现有图步数、模型调用次数和 token 预算共同限制，不能循环放大费用。前端 SSE 展示实际执行节点及“已验证/未验证/证据不足”，不把本地回退标记成模型验证成功。

图谱用独立的试验目录和明确的证据块白名单，首轮只含少量公开、非敏感的操作说明、含表格报告和基金相关章节。不能直接对整份大手册运行 `--max-docs 3`，因为单份可能有数百块；不得执行 LightRAG `--clear` 或修改旧图谱。若 LightRAG 服务不能报告逐次用量或隔离预算，图谱付费阶段保持关闭，先完成计量接入再试跑。抽取后必须核验实体/关系来源能映射回原文档与页码，不能把无法追溯的图谱边作为答案证据。

视觉通道先验证本地页图与视觉向量命中，再只对少量图片证据调用支持图像输入的 Pro 模型。图片输入费用按实际 `usage` 入账；未完成图像模型调用时只能称“视觉检索命中”，不能称“视觉内容已理解”。图像与文本证据同样必须有来源、页码和可打开的原图。

## 预算执行

1,500,000 tokens 是整个试跑的累计停机线，不是每个环节各有 150 万。初始分配仅为规划：图谱约 450,000；在线问答与双校验约 550,000；视觉案例约 150,000；回归评测约 100,000；故障重试与估算误差约 250,000。每一阶段根据首批实际 `usage` 调整**样本数量**，不抬高总上限。单个请求的成本以返回的输入、输出和思考 tokens 为准；资源包的实际抵扣仍以火山控制台为准。无足够预算预留则不发请求。在线服务可继续向真实用户提供有界问答；试跑预算耗尽后自动退回付费禁用/证据不足模式，不继续收费。

## 验收和停止条件

- 接入：探针返回目标模型及完整 `usage`，控制台确认资源包扣减；API Key 未泄漏，禁用开关仍有效。
- 问答：至少覆盖有答案文本题、跨文档题、表格题、视觉题、证据不足题和“掌上银行”歧义题；每题保留路由、检索、评分、生成、双校验及证据定位记录。错误银行名称必须被阻止，不能靠语言模型润色掩盖。
- 图谱：试验样本至少出现可追溯的实体/关系，缺少来源映射则不接入在线答案。
- 视觉：实际图片输入调用成功且引用页图可查看；只命中向量不算通过。
- 前端：SSE 节点事件与后端真实运行记录一致，失败和预算停止能明确呈现。
- 结束时交付用量与控制台余额对照、已测试样本、失败样本、尚未完成的付费/人工工作。不得宣称全库图谱完成或整体答案准确率通过。

任一 HTTP 402/429、模型不符、用量缺失、证据污染、来源不可追溯、异常抵扣或预算耗尽，立即暂停后续付费阶段并报告停在何处；不自动改用其他收费模型或绕过安全开关。
