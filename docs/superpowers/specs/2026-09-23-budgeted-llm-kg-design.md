# 有预算上限的大模型知识图谱设计

## 目标

对活动快照的真实文本切块调用已接入的 Doubao-Seed-2.1-pro，抽取带原文、页码和 chunk_id 的实体关系，形成可断点续跑且可作为可选检索通道的局部图谱。图谱试跑不能覆盖现有 920 份文档的在线文本/视觉索引，也不能通过 LightRAG 独立服务绕过 Ark 的统一 token 账本。

## 额度与覆盖边界

活动快照有 30,406 个文本切块、约 1,464 万字符；当前本地试跑账本最多批准 1,500,000 tokens，已使用约 18,032。全量付费图谱抽取明显超过此上限，本阶段按重要证据优先、在预算门禁处停止，不承诺 920 份全量图谱完成。优先顺序：当前评测候选中能映射到活动快照的 chunk_id，然后其他活动切块；每个切块至多调用一次。所有调用同时遵守 Ark 模型白名单、官方端点、用量回执校验和 `FINANCE_DISABLE_PAID_API` 开关。

## 抽取和持久化

新增独立命令从活动 `kb_v3_manifest.json` 和同目录 `chunks.jsonl` 读取；核对每条切块的 `snapshot_id`。调用模型时只发送一个有来源定位的切块，要求返回不超过 5 条结构化 `{head, relation, tail, evidence}`。`evidence` 必须是原切块的连续子串；否则拒收该条关系。输出保存于 `output/kg_pilot/` 下的 SQLite 检查点，不复制原文到日志。

调用前将切块标记为 `started`；返回的用量先由现有 `PilotBudget` 在共享账本结算，再把有效关系和 token 数保存为 `completed`。如果进程在远程调用期间退出，`started` 保留为 `needs_review`，不能自动重试以免重复计费。HTTP 402、429、用量缺失或预算不足时停止后续调用，记录准确的已完成/待核查/未处理数量。重复启动只跳过 `completed`，不重试需要人工核查的条目。

## 检索接入

图谱通道读取本地检查点，仅返回能够映射回活动快照现有 `chunk_id` 的关系；使用问题与实体/关系的词项匹配获得候选，再由现有 HybridRetriever 的 RRF 融合，不直接生成答案。仅在明确启用 `FINANCE_KG_PILOT_ENABLED=1` 时装配，且优先于无法计量的 LightRAG 服务；未启用或没有有效关系时原有文本/视觉检索不受影响。前端证据仍展示原始文档、页码和原文。

## 验收

- 无 Key、付费禁用、预算不足、无用量回执和响应格式错误都安全停止，不产生虚假 `completed`。
- 同一切块断点续跑不重复调用；不确定中的调用保留人工核查状态。
- 有效关系必须引用真实活动切块及原文片段；错误来源或跨快照关系不进入检索。
- 至少完成一条真实 Ark 抽取并保存其实际用量、来源和检索命中；报告完成数量、账本余额和未覆盖范围。
- 不改变活动快照，不声明答案准确率或 920 份全量图谱已完成。
